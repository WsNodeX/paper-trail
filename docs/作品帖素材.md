## 1. 一句话介绍

PaperTrail 是一个面向大学生的文献证据链工作台：把多篇论文摘要粘贴进来，纯浏览器本地整理成可追溯的证据矩阵、观点关系（支持/补充/冲突）与研究空白，并一键生成八模块综述工作包，全程不上传材料、不依赖外部模型。

## 3. 做了什么 / 为什么 / 怎么用 / 怎么与 Qoder 一起 built

### 做了什么（What）
一个单页 Web 工作台，含首页与四个功能页：导入材料、文献矩阵、观点关系、综述工作包。核心是一个本地规则引擎，把非结构化的论文摘要文本抽取为十字段结构，再推导文献间关系与研究空白，最终汇编成可导出的综述底稿。

### 为什么（Why）
大学生写综述时，常见痛点是：读了一堆摘要却记不清谁支持谁、谁和谁矛盾；手动整理证据表格耗时且容易漏掉来源；想继续研究却说不清「空白在哪、为什么值得做」。PaperTrail 把「整理—追溯—发现空白—成稿」这条链路工具化，并坚持每条结论都能点回原文证据，避免「看起来专业但无法核验」的 AI 幻觉式综述。

### 怎么用（How，≤5 步）
1. 打开首页，点「⚡ 一键体验示例（6 篇模拟论文）」立即看到完整结果；或进入「导入材料」粘贴自己的论文摘要。
2. 在「文献矩阵」查看每篇的研究问题/对象/方法/样本/结论/局限/证据完整度/来源标签，可搜索、按方法·年份·完整度筛选、排序；点任意行打开详情抽屉看可追溯证据。
3. 在「观点关系」看支持/补充/冲突关系图（手机自动切换为卡片列表），点冲突关系查看「为什么会有差异」的因子，点研究空白看「来源局限/为什么值得/怎样验证」。
4. 在「综述工作包」查看八模块底稿，可编辑主题/追问/提纲；每条结论附来源文献。
5. 复制 Markdown / 下载 Markdown / 打印 A4 报告，导出含生成时间与「请根据原文核验」提示。

### 怎么与 Qoder 一起 built（按轮次）
- 第 1 轮：用 Qoder 搭出分层骨架（数据/解析器/规则引擎/导出/状态/视图/应用），内置 6 篇虚构示例，跑通「示例→矩阵→关系→工作包→导出」闭环，首次部署到 Qoder Sites。
- 第 2 轮：矩阵扩到 10 列（增研究对象、来源标签），加方法/年份/完整度筛选与排序，手机端宽表转卡片，明确完整度计算规则，证据标注「示例材料」。
- 第 3 轮：关系节点显示年份，冲突关系附差异因子（样本/方法/时间/对象等），研究空白补「来源局限/为什么值得/怎样验证」三要素，区分「材料直接内容」与「整理推断的候选问题」。
- 第 4–5 轮：工作包支持用户编辑（主题/追问/提纲）且导出同步、不虚构来源；下载文件名含 PaperTrail+主题；导入提供逐篇字段识别小结与解析后字段编辑；空输入/坏格式/超大文件给出明确原因与修复建议。
- 第 6–7 轮：以评委首屏视角打磨首页与动词按钮，实测 375/768/1440 三档无横向溢出/无截断；清理调试代码，确认前端无密钥、无绝对路径、无外部请求。
- 第 8 轮：用 Qoder Sites 重新准备草稿并发布，设置为公开访问，实际打开公网地址跑通一键体验全流程。
- 第 9 轮：整理本客观作品帖素材。

## 8. 已知限制与后续计划

### 已知限制（如实说明）
- 当前为本地规则引擎，关系与空白基于关键词/句式/标签频次推导，属「辅助整理」，不是科学结论；存在误判可能，需人工核验。
- 内置 6 篇示例为虚构数据，仅用于演示闭环，均已标注「示例材料/虚构示例」，不可作为真实文献引用。
- 字段抽取依赖标注或启发式，对排版混乱/扫描版 PDF 复制出的文本识别率有限；PDF/Word 需先手动复制摘要文本。
- 数据仅存于当前页面内存，刷新即清空，暂不支持跨会话保存与多设备同步。
- 未接入真实大模型；预留接口尚未连接任何外部服务。

### 后续计划
- 接入预留的 `window.PaperTrailAdapter.analyze` 模型接口，提升关系/空白推导质量（异常时已可安全回退本地规则）。
- 增加可选的本地持久化（浏览器存储）与工程导出/导入，支持跨会话继续。
- 扩展更多文献类型与字段模板，优化自由文本抽取。

## 9. 能力来源三类标注（评委核验用）

- 【规则引擎/示例】关系推导、冲突因子、研究空白三要素、完整度计算、八模块汇编、6 篇示例数据——均由本地规则引擎产生；示例数据为虚构。这些是「工具能力」，不代表对真实文献的科学判断。
- 【用户输入推导】矩阵字段、证据片段、参考文献、工作包结论的来源编号——均来自用户实际粘贴/上传的材料；用户编辑的主题/追问/提纲标记为「用户编辑/用户补充」，新增行不自动绑定来源。
- 【未实现】真实大模型推理、跨会话持久化、多用户协作、PDF/Word 直接解析、外部文献库检索——当前版本均未实现，不在演示中宣称。

## 10. 用户应如何核验原文

1. 矩阵/抽屉/关系详情中的每条证据片段都带来源文献编号（如 E1-1）与「示例材料/输入材料」标识；点击编号可回到对应文献。
2. 示例文献为虚构，仅供体验流程，请勿引用；真实写作时请导入自己的材料。
3. 导出的 Markdown 与打印报告均含生成时间与「请根据原文核验」提示；关系理由与研究空白属「整理推断/候选问题」，引用前务必回到原文确认作者、年份、样本量与结论是否一致。
4. 完整度分数只反映「字段可追溯程度」（已识别字段数÷10），不代表研究质量高低。

## 11. 复现与重新部署（技术备查）

- 本地预览：`node tools/serve.mjs 4173`，访问 http://127.0.0.1:4173 。
- 核心自检：`node tests/run-tests.mjs`（19 项）；浏览器内「产品说明 → 运行自检」共用同一套断言。
- 构建：纯静态站点，无构建步骤；产物目录 `web/`（index.html + assets/style.css + js/）。
- 部署：Qoder Sites `prepare_site`（webDirectory=`web`，spa=false，复用 projectId）→ `publish_site` → 校验 `published:true` → `update_access_policy`（mode=public，confirmPublic=true）。
- 重新部署：修改 `web/` 源码后，用新的 actionId 重新 `prepare_site`（复用同一 projectId）→ `publish_site` → 校验，即可更新公网版本；公开访问范围保持不变。
