【P0-1｜摘要只显示前 3 条核心发现，与折叠区不一致】
位置：web/js/views.js:744 `var sumFindings = wp.synthesis.slice(0, 3).map(...)`；web/js/views.js:800 标题写死「核心发现 <small>按结果变量 · 前 3</small>」。
问题：示例 6 篇时 synthesis 有 5 条（P1 课堂注意力负向、P2 学业成绩负向、P4 知识掌握/测验成绩正向、P5 学习效率(自评)无显著、P6 学习投入/专注时长正向），摘要只渲染前 3 条，评委不展开折叠区就以为"只有负面结果"，且与方法分布"随机对照实验 1 篇/干预实验 1 篇"自相矛盾。
要求：
1) `sumFindings` 改为渲染全部条目（上限 8 条，>8 时尾部加"另有 N 条，展开查看"）；标题去掉"前 3"，改为「核心发现 <small>按结果变量 · 共 N 条</small>」，N 用 wp.synthesis.length。
2) 每个摘要条目必须同时显示：结果变量名、方向（正向/负向/无显著/方向未知）、有效篇数、来源编号、证据状态徽标（材料直接内容 / 跨材料归纳 / 候选推断，与 views.js:674 的 evStatus 保持一致）。
3) 摘要条目文案中性，只陈述方向，不加评价词。
验收：示例材料下摘要区必须同时出现 P1 负向、P2 负向、P4 正向、P5 无显著、P6 正向共 5 条，条数与「一、核心发现」折叠区完全一致；截图或 DOM 文本作为证据。

【P0-2｜核心发现文案是半成品内部日志口吻，且未测变量混入主题短语】
位置：web/js/core/engine.js:540 `else if (valid.length === 1) status = '材料仅 1 篇有效';`；web/js/core/engine.js:568-571 拼接的 stmt（"「X」：有效 1 篇（P1）方向一致为负向。"）；web/js/views.js:784 研究主题标题。
问题：a) status 字符串"材料仅 1 篇有效"直接显示给评委，像调试日志；b) 单篇有效时 stmt 用"方向一致"措辞，1 篇谈不上"一致"；c) 主题短语会把仅被明确标为未测的学习变量词并入主题侧。
要求：
1) 状态词改为面向读者的表述：validCount>=2 → 「跨材料归纳」；validCount===1 → 「单一来源」；validCount===0 → 「暂无直接证据」。同步检查 views.js 的 evStatus 与 exporter.js:78 的状态输出，三处措辞一致。
2) 单篇 stmt 改写为可读断言，例如："「课堂注意力」：目前仅 P1 一篇直接证据，方向为负向；样本有限，仅作方向参考，需补充验证。"多篇仍用"方向一致/方向不一致"。
3) 多篇且 propMix（自变量/设计不同）时保留现有"属并列结果"提示；单篇不出现该提示。
4) 主题短语（topic）只由"已实际测量并报告结果"的结果变量构成；仅存在于 p.boundaries 的变量词不得进入主题短语，只能出现在「数据边界」模块。
验收：示例材料下摘要不出现"材料仅 1 篇有效"字样；三处状态词一致；替换导入 U1/U2/U3 后，主题短语不出现"知识掌握/测验成绩/学习效率"这些 U1 明示未测的变量（U2/U3 若确实测量了则允许出现），"数据边界"仍列出 U1 三项未测。

【P0-3｜768px 宽度文献矩阵被裁切，无横向滚动入口】
位置：web/js/views.js 矩阵表渲染（web/js/views.js:312 附近 `<td class="cell-src">`）；web/index.html 中矩阵容器；web/assets 下表格样式。
实测：768px 视口下 table 宽 1080px、容器 758px，右侧列被裁，且没有横向滚动条。375 与 1440 正常。
要求：
1) 矩阵容器加 `overflow-x: auto; -webkit-overflow-scrolling: touch;`，滚动条出现时不遮挡首列（首列 sticky left 可选）。
2) 768–1024px 提供紧凑列模式：默认只保留 标题 / 年份 / 方法 / 核心结论 四列，其余列（研究问题、样本、局限、来源标签）改为行内"展开详情"或在卡片视图显示；宽度 ≥1200px 恢复全列。
3) 表格文字保持 13px 以上可读；宽度用容器滚动或列折叠解决。
验收：768、820、1024 三个宽度各记录 `document.documentElement.scrollWidth`、容器 `clientWidth`、`scrollWidth`、table 宽度，证明可横向滚动或已切紧凑列；375 与 1440 仍需回归不新增横溢。

【P1-4｜A4 打印在生产环境点击后主框架无响应】
位置：web/js/app.js:242-248 `printReport()`（同步 `printRoot.innerHTML = views.printReport(s)` 后 `setTimeout(window.print, 250)`）；web/js/views.js:937 `printReport(s)` 一次性拼整份 HTML；web/index.html:66-67 `#print-root`。
问题：点"打印 A4 报告"后页面报 `PageUnresponsiveError: did not answer Runtime.evaluate within 15000ms: a main-frame navigation had started but not committed.`，打印预览从未打开；一次同步 innerHTML 拼全量报告造成长任务。
要求：
1) 改为隐藏 iframe 打印：创建 iframe（`position:fixed;width:0;height:0;border:0`）→ 写入 `<!doctype html><html><head>` + 打印样式 + `</head><body>` → 分块 append 或 `contentDocument.write` 后调用 `iframe.contentWindow.print()`；主页面不导航、不阻塞。
2) 生成过程保持主线程可响应：按模块（八节）分块 `await new Promise(r => setTimeout(r, 0))`，一次只拼一节；先渲染骨架再逐节补内容。
3) `window.print` 抛错或 iframe 未就绪时：显示可见错误 toast，并自动提供"下载 Markdown"作为降级动作，失败路径必须给可见反馈。
4) 打印样式：A4 纵向、`@page { size: A4; margin: 14mm }`、`break-inside: avoid` 用于模块标题+首段、每页页脚"PaperTrail · 研究主题 · 第 N 页"（用 CSS `@page` counter 或打印时切分容器实现其一，能做哪个做哪个并说明）。
5) 保留 `#print-root` 兼容旧路径，但不再作为唯一渲染目标；`beforeprint` 监听改为使用 iframe 方案后移除或简化实现，避免二次渲染。
验收：真实点击"打印 A4 报告"后，主页面在 3 秒内仍能响应（点开导航或滚动正常），打印预览/PDF 成功打开；用 CDP `Page.printToPDF` 实测并报告页数、是否含标题/数据边界/引用三节、是否出现空白页、页脚页码是否出现。
